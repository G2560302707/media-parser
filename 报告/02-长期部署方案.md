# media-prism 长期部署方案（可执行）

最优方案已经按「要对外开放、要养抖音实况 Cookie、机器是 Windows Server」选定。下面按这个方案写，能直接施工。

---

## 0. 最优架构（选定）

**一台带桌面的 Windows Server（家庭/办公宽带，固定公网 IP）+ Docker Desktop 跑 Linux 容器 + 同一台机器上的火狐保持抖音登录。**

为什么是这个，而不是云主机或 `python app.py`：

| 方案 | 为什么不作为最优 |
| --- | --- |
| 阿里云 / 腾讯云 Linux | 机房 IP，抖音实况、部分小红书会 403 / 跳登录 |
| 云上 Windows Server | 操作系统对了，出口仍是机房 IP |
| 本机 `python app.py` | `app.py` 使用 Unix `fcntl`，Windows 原生会挂 |
| `API_ONLY=true` 裸奔公网 | 无 API Key、无调用日志，不能对外开放 |
| 解析在云上、Cookie 从家里导出 | 登录 IP 和请求 IP 不一致，Cookie 容易当场失效 |

选定方案的要点：**浏览器会话、解析进程、出口 IP 三者在同一台宽带机器上。**

```
调用方 HTTPS
    → 防火墙只放 443（或反代端口）
    → Caddy / Nginx（TLS + 限流）
    → 127.0.0.1:8051  Docker 容器 media-prism
         API_ONLY=false
         读后台热配置里的 DOUYIN_COOKIE / XHS_COOKIE
    旁路：Windows 用户自动登录
         火狐常开抖音网页版
         计划任务读 cookies.sqlite → 写入后台凭据
```

---

## 1. 机器准备

1. Windows Server **带桌面体验**，不要 Server Core。
2. 固定宽带、公网 IP 或稳定 DDNS。关掉睡眠。
3. 专用本地用户，例如 `parser`。开机自动登录到该用户（AutoLogon）。火狐必须跑在这个交互会话里，不能做成 Session 0 服务。
4. 安装：Docker Desktop（Linux 容器）、Firefox、可选 Caddy。
5. 远程桌面不要对公网裸放 3389。走 VPN 或限制来源 IP。
6. 磁盘 BitLocker。用**专用平台账号**登录抖音/小红书，不要用日常主号。

---

## 2. 容器部署（一次做完）

在 `media-prism` 目录：

```powershell
copy .env.example .env
```

`.env` 必改项（对外开放）：

```env
API_ONLY=false
TRUST_PROXY_HEADERS=true
TZ=Asia/Shanghai
SECRET_KEY=换成一长串随机字符
```

**不要**在 `.env` 里长期贴完整 Cookie（会进备份和镜像层）。Cookie 走容器起来后的后台「系统设置 → 平台凭据」，热更新、不必重建容器。

启动：

```powershell
cd D:\Tabletop\桌面项目BOX\ParsingTool\media-prism
docker compose up -d --build
docker compose logs -f web
```

- 端口：`8051`（只绑本机，由 Caddy 反代）。
- 数据：`./data`（SQLite：用户、API Key、设置、日志）。
- 日志：`./logs`。
- 健康检查：容器内 `GET /api/health`。

首次访问（仅内网）：

1. 打开 `http://127.0.0.1:8051/auth/setup` 创建管理员。
2. 关掉注册或仅邀请；在后台签发 API Key（`mp-` 开头）。
3. 按平台需要打开/关闭解析开关和 QPS。
4. 不要把 `/auth/setup` 暴露到公网（初始化后入口会关，仍建议反代不转发该路径）。

进程形态（镜像默认）：

```text
gunicorn --workers 2 --threads 4 --worker-class gthread --timeout 120 --bind 0.0.0.0:8051 app:app
```

解析预算约 90 秒，超时 120 秒匹配。

## 3. 对外入口（必须有 TLS）

Caddy 示例（把域名换成真实域名）：

```caddy
parse.example.com {
    reverse_proxy 127.0.0.1:8051
    encode gzip
    header {
        -Server
        Strict-Transport-Security "max-age=31536000"
    }
    @setup path /auth/setup*
    respond @setup 404
    rate_limit {
        zone dynamic {
            key {remote_host}
            events 30
            window 1m
        }
    }
}
```

Windows 防火墙：入站只放 80/443。Docker 的 8051 仅监听 localhost（可在 compose 改成 `"127.0.0.1:8051:8051"`）。

## 4. Cookie 运维（长期能跑的关键）

### 4.1 什么时候需要 Cookie

| 场景 | 要不要 |
| --- | --- |
| 抖音普通视频 / 普通图文 | 通常不要 |
| 抖音实况轨 | 要：完整登录 Cookie + `UIFID` |
| 小红书（机房或风控） | 要：`a1` / `webId` / `web_session` |
| 视频号 | 要：元宝 `hy_user` / `hy_token`（未实测） |

### 4.2 更新节奏（不要盲着重登）

1. 火狐保持登录，不必关掉。
2. 每 30–60 分钟跑金丝雀：
   - 抖音实况：`https://v.douyin.com/ZtiyRAA2JLs/`，成功条件是 `image_list` 里仍有 `live_photo_url`。
   - 小红书短链：测试集里任一条，成功条件是有 `video_url` 或 `image_list`。
3. 失败 → 告警（邮件 / 飞书），管理员在这台机器的火狐里重新登录一次，再跑「从 cookies.sqlite 导入后台」脚本。
4. 后台保存凭据立即生效，不用重启容器。

禁止：

- 自动打平台登录接口、过验证码。
- 收集调用方浏览器 Cookie。
- 把 Cookie 打进日志或返回给调用方。

Cookie 脚本只允许读本机 `%APPDATA%\Mozilla\Firefox\Profiles\*\cookies.sqlite` 的副本（先复制再打开，避免火狐锁库）。

## 5. 日常巡检清单

| 频率 | 动作 |
| --- | --- |
| 每分钟（容器自带） | `/api/health` |
| 每小时 | 金丝雀 3 条：抖音视频、抖音实况、B 站视频 |
| 每天 | 跑一遍 `测试集`；看后台失败率、429、Cookie 错误码 |
| 每周 | 看 Docker 日志、磁盘 `data/` 体积、Windows 更新是否把自动登录冲掉 |
| 平台大改版后 | 对应解析器失效时，后台关掉该平台并通知调用方 |

金丝雀失败判定：

- `MEDIA_DELETED_OR_PRIVATE`：换一条备用公开链接，不是服务挂了。
- `XIAOHONGSHU_COOKIE_REQUIRED` / 实况没有 `live_photo_url`：养号问题。
- `INTERNAL_ERROR` / 健康检查失败：进程问题。

## 6. 备份与恢复

备份目录：`media-prism/data/`（含 SQLite 和 `.secret_key`）。不要备份火狐整盘到公网网盘。

恢复：停容器 → 覆盖 `data/` → 启动。API Key 在库里，调用方不用换 Key。Cookie 仍以当时火狐会话为准，恢复后跑一次导入。

## 8. 以后若必须上云

解析容器可以上云，但**发往抖音/小红书的出口必须仍走这台宽带机器**（住宅代理或反向隧道）。只把 Cookie 字符串拷到云主机，通常会立刻失败。
