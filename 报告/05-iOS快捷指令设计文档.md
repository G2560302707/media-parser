## 0. 一句话

做一个叫「媒体解析」的 iOS 快捷指令：用户从抖音、小红书等 App 点分享，或者复制口令后点桌面图标，**自动带上自己的 API Key 调解析接口，把视频/图片存进相册**。

日常路径零菜单。密钥、保存偏好、实况图怎么处理——能选的都放到设置里，默认值让 90% 的人永远不用打开设置。

---

## 1. 设计原则

1. **密钥必传。** 生产环境是运营模式（`API_ONLY=false`），没有 Key 就是 401。快捷指令不能做成「免登录体验页」的移动版。
2. **现在没有付费。** 不出现购买、充值、套餐。积分耗尽只说「请联系管理员」，不引导付款。
3. **注册拿密钥这条路必须短。** 现在是：注册 → 再登录 → 进控制台 → 点创建 → 起名字 → 复制。对手机用户太长，要压到「注册完就能复制一把现成的钥匙」。
4. **日常使用零思考。** 分享出去就能下。问东问西的选择全部进「媒体解析 · 设置」。
5. **能给的选择都给，但不挡路。** 每种选择都有可工作的默认值。
6. **更新快捷指令不能把用户的 Key 冲掉。** Key 不写死在指令内部。
7. **用现有接口，不发明新鉴权。** 继续 `POST /api/v1/parse` + `Authorization: Bearer mp-...`。不为快捷指令单独做 OAuth、邮箱魔法链接、扫码登录。

## 2. 现状（已核对代码，不拍脑袋）

### 2.1 解析接口

| 项 | 实际值 |
| --- | --- |
| Base URL | `https://after7lab.cloud:81` |
| 业务接口 | `GET` / `POST /api/v1/parse`（`/api/parse` 是免 Key 的体验接口，快捷指令**不用**） |
| 健康检查 | `GET /api/health` → `{"status":"ok"}` |
| 鉴权 | Header `Authorization: Bearer mp-...`（推荐）或 Query `?key=` |
| 入参 | `text` 或 `url`，整段分享口令可原样传入 |
| 长度 | 代码上限 **2000** 字符（`src/api/parse.py` 的 `MAX_TEXT_LENGTH`）。接口文档里写的 2048 是过时数字，快捷指令按 2000 截断 |
| 成功判断 | 永远看 `succ`（布尔），不要只看 HTTP 状态码 |
| 媒体直链 | 有时效，拿到立刻下载 |
| QPS | 新用户默认 2 次/秒 |

### 2.2 密钥从哪来

```
用户注册（用户名 ≥3，密码 ≥8）
    → 账号写入 users（试用天数 / 积分 / QPS 走后台默认值）
    → 目前不会自动创建 API Key
    → 用户还得再登录，进 /console/keys，手动点「创建 API Key」
    → 密钥形如 mp- + 24 位字母数字，账号最多 10 把
    → 明文可反复查看、复制（不是一次性显示）
```

注册默认：试用 365 天、赠送 100 积分、QPS=2。后台可以把积分改成「不限制」（`-1`）。**当前没做付费**，但 100 积分用完会返回 `402 INSUFFICIENT_CREDITS`。快捷指令必须接住这个错误，运营侧建议把面向快捷指令用户的默认积分改成不限制，否则用户会莫名其妙解析失败。

### 2.3 成功时 `data` 里快捷指令真正用到的字段

| 字段 | 用途 |
| --- | --- |
| `platform` / `author.nickname` / `title` | 完成通知 |
| `desc` | 可选：复制文案 |
| `video_url` | 主视频，存相册 |
| `video_list` | 多视频时逐条下载（首项与 `video_url` 相同） |
| `image_list` | 图集。元素可能是字符串，也可能是 `{url, live_photo_url}` |
| `audio_url` | 音频，存到文件 |
| `cover_url` | 默认不存，设置里可打开 |
| `is_preview` / `full_duration` | 试听片段提示（汽水音乐等） |

`image_list` 必须按元素类型分支，不能假设全是 URL 字符串。

### 2.4 现有缺口

- 仓库里没有任何快捷指令、iCloud 链接、安装页。
- 注册成功只跳登录页，不展示密钥。
- 首页 CTA 是「在线解析 / 查看 API 示例」，没有「用 iPhone 下载」入口。
- 密钥创建需要用户自己起名，手机上又多一步。

## 3. 目标用户与成功标准

**主用户：** iPhone 上刷抖音 / 小红书 / 快手，想把作品存进自己相册的人。他们不会看接口文档，也不会用 curl。

**次用户：** 已经有账号的人，只想把现有 Key 填进手机。

**成功标准（日常）：**

1. 抖音点分享 → 快捷指令 → 10～20 秒内视频进相册。
2. 全过程不弹「请输入密钥」（非首次）。
3. 失败时能看懂原因（直接展示接口返回的 `retdesc`）。

**成功标准（首次）：**

从「我不知道这个服务」到「第一次成功存视频」，不超过下面 4 步：

1. 安装快捷指令
2. 注册（或登录）
3. 复制那把已经生成好的密钥
4. 在快捷指令里粘贴一次

## 4. 产品形态：1 + 1 条快捷指令

只做两条，不再拆第三条「仅复制链接」「仅下音频」。那些都是主指令里的保存模式。

| 指令 | 谁用 | 干什么 |
| --- | --- | --- |
| **媒体解析** | 每天 | 收分享/剪贴板 → 带 Key 解析 → 按偏好保存 |
| **媒体解析 · 设置** | 偶尔 | 填/换密钥、改保存偏好、测连通、打开注册页 |

主指令内部也藏一条「未配置密钥时自动走设置流程」，所以**只装主指令也能用**。设置指令是给想改偏好、换 Key 的人的快捷入口，不是必装。

不采用的方案：

- 五六条按平台拆的指令（抖音一条、小红书一条）——接口已经自动认平台。
- 把 Key 写死在分享出去的指令里——更新指令会覆盖，也容易把 Key 泄漏给下一个安装的人。
- 依赖 Data Jar / Toolbox Pro / Scriptable——能用系统能力就用系统能力。
- 快捷指令内嵌 WebView 登录——iOS 快捷指令做不好会话，项目也没有 OAuth。

## 5. 密钥：怎么拿到、怎么配、怎么换

这是本设计最重要的一章。原则：**网站负责发钥匙，快捷指令负责收钥匙并记住。两边都不发明第二种身份。**

### 5.1 三种拿钥匙的路（都保留）

用户从主指令首次运行，或从设置指令点「配置密钥」，看到三个选项：

```
┌─────────────────────────────────────┐
│  还没有密钥                          │
│                                     │
│  [ 去注册，自动给我一把 ]   ← 默认   │
│  [ 我已有账号，去控制台复制 ]        │
│  [ 我已经复制好了，现在粘贴 ]        │
└─────────────────────────────────────┘
```

| 选项 | 发生什么 | 给谁 |
| --- | --- | --- |
| 去注册 | 用 Safari 打开 `https://after7lab.cloud:81/auth/register?from=shortcut` | 新用户 |
| 去控制台 | 打开 `https://after7lab.cloud:81/console/keys`（未登录会跳到登录） | 老用户 |
| 现在粘贴 | 弹出输入框；若剪贴板以 `mp-` 开头，预填剪贴板 | 钥匙已经在剪贴板里的人 |

管理员代开账号、口头把 Key 发给用户，走第三条即可。不单独做「兑换码」「邀请码」。

### 5.2 网站侧：把「拿钥匙」压到最短

**改动 1 — 注册成功自动登录，并自动创建一把密钥。**

注册成功后不要再丢去登录页。服务端立刻：

1. 写入 `users`
2. 自动 `generate_api_key()`，插入 `api_keys`，名称固定为「快捷指令」
3. `session["user_id"]` 直接登录
4. 跳到欢迎页 `/console/welcome`，把这把 Key 明文放在最中间，配一个「复制密钥」主按钮

用户已经在控制台里手动建过密钥的，行为不变。只对**这次注册新建的账号**自动建一把。若极端情况下账号已有 ≥10 把（基本不会发生在刚注册），跳过自动创建，欢迎页改口「请到密钥页新建」。

**改动 2 — 欢迎页只干三件事。**

```
┌──────────────────────────────────────────┐
│  注册成功，这是你的密钥                    │
│                                          │
│  mp-xxxxxxxxxxxxxxxxxxxxxxxx             │
│  [ 复制密钥 ]                            │
│                                          │
│  1. 复制上面这串                         │
│  2. 回到「快捷指令」App 打开「媒体解析」   │
│  3. 选「现在粘贴」                        │
│                                          │
│  [ 我也去安装快捷指令 ]  [ 先去控制台 ]   │
└──────────────────────────────────────────┘
```

手机上这是一屏就能看完的。密钥在控制台随时能再复制，所以欢迎页不必搞「只显示一次」的紧张感（项目现有密钥页本来就可以反复查看明文）。

**改动 3 — 快捷指令落地页 `/shortcut`。**

给安装链接、三步图、注册/登录入口。首页导航加一项「iPhone 快捷指令」指过来。详情见第 11 章。

**改动 4 — 密钥页加一句人话。**

「把密钥粘进 iPhone 的『媒体解析』快捷指令即可。更新快捷指令不会冲掉已保存的密钥。」旁边保留现有的复制按钮。

### 5.3 快捷指令侧：钥匙存在哪

三选一，默认 iCloud。设置里可改。

| 方式 | 路径 | 优点 | 缺点 | 默认？ |
| --- | --- | --- | --- | --- |
| **iCloud 文件** | `iCloud Drive/Media Parser/api-key.txt` | 换指令、换手机（同一 Apple ID）都还在 | 用户关了 iCloud 云盘会失败 | **是** |
| **本机文件** | `我的 iPhone/Media Parser/api-key.txt` | 不依赖 iCloud | 换机要重配 | 备选 |
| **每次询问** | 不落盘 | 共用设备、临时测试 | 每天都要贴 | 备选 |

**明确不采用：** 把 Key 写进快捷指令内部的「文本」动作。分享/更新指令时会泄漏或被覆盖。仅作为「高级用户自己改指令」的逃生口，文档里提一句，设置 UI 不推荐。

配套再存一个偏好文件：

```
iCloud Drive/Media Parser/settings.json
```

密钥文件只放一行 `mp-...`，不要混进 JSON，方便用户用「文件」App 直接改。

### 5.4 粘贴时怎么校验（不新增接口）

1. 去空格、去前后引号。
2. 正则：`^mp-[A-Za-z0-9]{24}$`。不符 → 「这不像密钥，应为 mp- 开头的一串」。
3. 发一次 **不带 `text` 的** `POST /api/v1/parse`（Header 仍带 Bearer）：
   - `401 INVALID_API_KEY` / `API_KEY_REQUIRED` → Key 无效，不保存
   - `400 INVALID_TEXT` → Key 有效（空文本在扣积分之前就返回，不耗额度）
   - `403` / `402` → Key 能识别，但账号停用/到期/积分耗尽，**仍然保存**，并弹出对应 `retdesc`
   - 网络失败 → 先问「仍要保存吗？」

保存成功给一句：「已记住。以后从 App 点分享即可。」

### 5.5 换密钥、多设备、注销

- **换 Key：** 打开「媒体解析 · 设置」→「更换密钥」→ 覆盖 `api-key.txt`。
- **多设备：** iCloud 方式下第二台 iPhone 装同一条指令，第一次就会读到已有文件，不再询问。
- **登出：** 设置里「删除本机密钥」。只删文件，不动服务器上的 Key。
- **服务器删了 Key：** 下次解析拿到 401，主指令提示「密钥失效，去重新配置」，一键跳设置。

### 5.6 为什么不做的几种「更酷」方案

| 方案 | 不做的原因 |
| --- | --- |
| 快捷指令里直接填用户名密码换 Token | 项目没有 Token 接口；密码进快捷指令比 Key 更危险 |
| 注册接口改成 JSON 给快捷指令调用 | 快捷指令里填表比 Safari 里填更差，还要处理 CSRF |
| 用 `shortcuts://run-shortcut?input=mp-xxx` 从网页回填 | URL 会进历史，也不稳定 |
| 扫码把 Key 传进手机 | 多一个生成二维码的后端，对单用户过重 |

Safari 复制 + 快捷指令粘贴，是 iPhone 上最短且用户已经会的动作。

## 6. 主指令「媒体解析」：日常流程

### 6.1 入口（全部支持，按优先级自动选）

安装时勾选「显示在分享表单」，接收类型：**文本、URL、Safari 网页**。

运行时取输入，优先级：

1. **分享表单传入了内容** → 直接用（抖音/小红书「分享 → 快捷指令」主路径）
2. **否则看偏好 `input`：**
   - `smart`（默认）：剪贴板看起来像链接或分享口令（含 `http://` / `https://`）就用剪贴板；否则弹出「粘贴分享内容」
   - `clipboard`：无条件用剪贴板
   - `ask`：每次询问
   - `share_only`：不是从分享进来的就提示「请从 App 点分享」

可从这些地方唤起，不用额外开发：

- App 分享菜单（主路径）
- 主屏幕图标
- 锁屏小组件 / 控制中心按钮
- 操作按钮（iPhone 15 Pro 及更新）
- 背面轻点
- Siri：「嘿 Siri，媒体解析」（走剪贴板 / 询问）

### 6.2 主干（有 Key 之后）

```
取到分享文本
  → 截断到 2000 字
  → POST https://after7lab.cloud:81/api/v1/parse
       Header: Authorization: Bearer <key>
               Content-Type: application/json
               Accept: application/json
       Body:   {"text": "<原文>"}
  → 解析 JSON
       succ == false  → 第 9 章错误处理，结束
       succ == true   → 按 data 形态保存（第 7 章）
  → 通知：「已保存 · 抖音 · @昵称 · 标题前 40 字」
```

默认路径**没有任何菜单**。视频就存视频，图就存图，混排就都存。

### 6.3 为什么用 POST + Header，不用文档里的 GET 示例

GET `?key=&url=` 能跑，但：

- Key 会出现在服务器访问日志、可能的代理日志里
- 中文口令 + 表情做 Query 编码，快捷指令更容易踩坑
- 官方文档自己也写「POST 时推荐 Header」

快捷指令的「获取 URL 内容」原生支持自定义 Header 和 JSON Body，没有理由走兼容模式。

健康检查 `GET /api/health` **不每次都打**。只在：首次配 Key、解析出现网络错误、用户在设置里点「测试连通」时使用。

## 7. 保存逻辑：按内容形态，不按平台

接口已经归一。快捷指令只认字段在不在，不认「这是不是抖音」。

### 7.1 决策表

按顺序检查，可以同时成立（图文 + 视频的作品两样都存）：

| 条件 | 默认动作 | 设置项可改成 |
| --- | --- | --- |
| `video_url` 有值 | 下载，存相册（视频） | 改存文件；只要直链；每次问 |
| `video_list` 长度 > 1 | 逐条下载全存 | 只要第一条；每次问 |
| `image_list` 有值 | 见 7.2 | — |
| `audio_url` 有值 | 下载，存到「文件 / Media Parser / 音频」 | 忽略；每次问 |
| `cover_url` 有值 | **默认不存**（视频封面通常多余） | 打开后一并存图 |
| `is_preview == true` | 仍保存音频，通知里加「试听片段，完整约 N 秒」 | — |
| 以上都没有，但有 `title`/`desc` | 不报「成功」，提示「没有可下载的媒体」+ 可复制文案 | — |

文件名（存到「文件」时）：用 `title` 去掉 `\ / : * ? " < > |`，空则用 `video_id` 或时间戳。存相册不需要文件名。

多图超过 30 张：默认仍全下，但先通知「共 N 张，开始保存」。不强制确认（图集 30+ 在小红书常见，多一次确认会烦）。设置里可打开「超过 N 张先问我」。

### 7.2 `image_list` 混合形态（必须兼容）

对数组里**每一个元素**：

```
如果 元素 是词典：
    这是实况图
    按偏好 livePhoto：
      video  → 下载 live_photo_url，存相册（视频）     ← 默认
      still  → 下载 url，存相册（图片）
      both   → 两个都存
      ask    → 这一组只问一次，后面的实况沿用这次选择
    若 live_photo_url 为空，退回存 url
否则：
    元素就是图片直链字符串，存相册（图片）
```

**能力边界（写进设置页的说明，不要假装能做到）：**

iOS 快捷指令**不能**把一对图+视频写成系统「实况照片」（需要匹配的 `contentIdentifier`，系统动作没有这个能力）。默认把实况轨当视频存，用户仍能在相册里播放这段动态。若以后用 Scriptable 做真正的 Live Photo，作为可选高级路径，不进 v1。

### 7.3 下载失败

媒体 CDN 偶发拒无 UA 的请求。快捷指令「获取 URL 内容」自带 Safari UA，一般够用。若单条失败：

1. 同一 URL 再试一次
2. 仍失败：把这条 URL 放进「失败列表」，继续下一条（图集不要一张失败就全停）
3. 全部结束后若有失败：通知「保存了 M 项，N 项失败」，并提供「复制失败链接」

视频可能几百 MB。快捷指令把文件先载入内存再存相册，超大文件可能内存告急。失败时补一句「可改用『只要直链』模式，用其他下载器打开」。不在 v1 做分片下载。

### 7.4 保存模式（设置里四选一）

| 值 | 含义 |
| --- | --- |
| `album`（默认） | 视频/图片进相册，音频进文件 |
| `files` | 全部进 `文件 / Media Parser / 下载` |
| `links` | 不下载，把直链和文案做成一段文本放入剪贴板 |
| `ask` | 每次解析成功后问一次上面三项 |

`links` 模式输出示例：

```
抖音 · @昵称
标题……

视频：
https://...

图片：
https://...
```

给想用 Documents、nPlayer、电脑下载的人。

## 8. 设置项总表（能选的都在这）

文件：`settings.json`。缺字段用默认。主指令读不到文件就当全默认，不报错。

```json
{
  "version": 1,
  "keyStorage": "icloud",
  "input": "smart",
  "saveMode": "album",
  "livePhoto": "video",
  "multiVideo": "all",
  "saveCover": false,
  "saveAudio": true,
  "maxImagesAsk": 0,
  "copyDesc": false,
  "notify": true,
  "confirmClipboard": false
}
```

| 键 | 默认 | 用户能选什么 | 为什么给这个选择 |
| --- | --- | --- | --- |
| `keyStorage` | `icloud` | iCloud / 本机 / 每次问 | 有人关云盘，有人共用设备 |
| `input` | `smart` | 智能 / 只用剪贴板 / 每次问 / 只用分享 | 桌面图标用户 vs 分享菜单用户习惯不同 |
| `saveMode` | `album` | 相册 / 文件 / 只要链接 / 每次问 | 不是所有人都要进相册 |
| `livePhoto` | `video` | 当视频 / 当静图 / 都要 / 每次问 | 实况图有人只要封面 |
| `multiVideo` | `all` | 全部 / 只要第一条 / 每次问 | 公众号多视频可能很长 |
| `saveCover` | `false` | 要 / 不要 | 视频用户通常嫌封面重复 |
| `saveAudio` | `true` | 要 / 不要 / 每次问 | 纯听音乐的人需要，刷视频的人可能不要 |
| `maxImagesAsk` | `0`（0=不问） | 0 / 20 / 50 | 超大图集的人想先确认 |
| `copyDesc` | `false` | 要 / 不要 | 做二创的人要文案 |
| `notify` | `true` | 要 / 不要 | 有人嫌通知烦 |
| `confirmClipboard` | `false` | 要 / 不要 | 打开后，用剪贴板前先预览前 80 字确认 |

「媒体解析 · 设置」的菜单就按这张表做，每项一个「从列表中选取」，选完写回 JSON。另加四个动作：

- 配置 / 更换密钥
- 删除本机密钥
- 测试连通（health + 一次空 parse 验 Key）
- 打开注册页 / 密钥页 / 安装说明页

## 9. 错误处理

判断永远以 JSON 的 `succ` 为准。展示永远优先 `retdesc`（接口已经写给人看的）。`error_code` 只用来决定**要不要多给一个按钮**。

| error_code | 额外动作 |
| --- | --- |
| `API_KEY_REQUIRED` / `INVALID_API_KEY` | 按钮「重新配置密钥」→ 跳设置 |
| `API_KEY_DISABLED` / `ACCOUNT_EXPIRED` | 按钮「打开控制台」；文案保持 `retdesc` |
| `INSUFFICIENT_CREDITS` | **不出现付费字样**。展示 `retdesc`，按钮「打开控制台」 |
| `RATE_LIMITED` / `PLATFORM_RATE_LIMITED` | 等 1 秒，自动重试 **一次**；再失败才展示 |
| `MEDIA_DELETED_OR_PRIVATE` / `NO_MEDIA_IN_CONTENT` / `PLATFORM_NOT_SUPPORTED` | 只展示，不重试 |
| `INVALID_TEXT` / `URL_NOT_FOUND` / `TEXT_TOO_LONG` | 「请重新复制分享链接」 |
| `REDIRECT_FAILED` / `MEDIA_NOT_FOUND` | 「稍后重试」 |
| `*_COOKIE_REQUIRED` | 只展示。这是服务端 Cookie 问题，用户改不了 |
| `API_DISABLED` / `PLATFORM_DISABLED` | 只展示 |
| `INTERNAL_ERROR` | 「服务端忙，稍后重试」 |
| 网络层失败（快捷指令没拿到 JSON） | 先打 `/api/health`：通 → 「解析服务异常」；不通 → 「当前网络访问不了 after7lab.cloud:81，请确认蜂窝/Wi-Fi 和证书」 |

401 时**不要**立刻把本地 Key 删掉。有可能是复制少了字符；让用户自己在设置里覆盖。

## 10. 主指令动作清单（给之后在 iPhone 上搭建用）

用系统中文动作名，按执行顺序。括号里是配置要点。

1. **注释** — 名称、版本（如 `media-parser-shortcuts 1.0`）、服务地址
2. **接收输入** — 分享表单；类型：文本、URL、Safari 网页
3. **获取文件** — `Media Parser/api-key.txt`（iCloud，不问位置）
4. **如果** 文件不存在或为空
   - **从列表中选取** 注册 / 去控制台 / 现在粘贴（第 5.1 节）
   - 前两项：**打开 URL**
   - 第三项：走校验与保存（第 5.4 节），然后 **停止**
5. **设置变量** `APIKey`
6. **获取文件** `Media Parser/settings.json`（没有则用内置默认词典）
7. **如果** 快捷指令输入为空
   - 按 `input` 偏好取剪贴板或 **询问**
8. **文本** 截取输入前 2000 字 → 变量 `ShareText`
9. **获取 URL 内容**
   - URL：`https://after7lab.cloud:81/api/v1/parse`
   - 方法：POST
   - Header：`Authorization` = `Bearer {APIKey}`；`Content-Type` = `application/json`
   - 请求正文：JSON，字段 `text` = `ShareText`
10. **获取词典** ← 响应
11. **获取词典值** `succ`
12. **如果** `succ` 不是 true → 第 9 章分支 → **显示结果** / **显示通知** → **停止**
13. **获取词典值** `data`
14. 按第 7 章逐项下载
    - **重复** `image_list` / `video_list`
    - **如果** 重复项 **类型为词典** → 实况分支
    - **获取 URL 内容**（媒体直链，方法 GET，不额外加 Header）
    - **存储到相册** 或 **存储文件**
15. **如果** `copyDesc` → **复制到剪贴板**（`desc`）
16. **显示通知**（若 `notify`）
17. **如果** `saveMode == links` → 拼文本，**复制到剪贴板**，通知「直链已复制」

搭建时注意：

- 「获取 URL 内容」对 JSON 勾选「显示网页内容」关掉，拿原始数据。
- 媒体下载那一步超时尽量拉满；失败不要让整个快捷指令崩溃（用「如果」包住）。
- 不要在分享出去的副本里残留真实 Key。
- 中文 iOS 与英文 iOS 动作名不同，对外安装包用一台中文 iPhone 导出即可，系统会本地化。

## 13. 安全与隐私

- 对外分发的快捷指令**不含**任何真实 Key，只有占位逻辑。
- Key 只存在用户自己的 iCloud / 本机文件，服务端不知道用户把 Key 存哪了。
- 用 POST Body 传分享文本，Key 走 Authorization Header。
- 欢迎页、密钥页已有的「复制」会把 Key 放进剪贴板——这是用户主动操作。快捷指令首次若剪贴板以 `mp-` 开头可预填，但要在输入框里可见，让用户确认后再保存。
- 设置页写清：「不要把已经填过密钥的快捷指令副本发给别人。请让他们安装官方版本，用自己的密钥。」
- 现有密钥哈希逻辑（`hash_api_key`）与本次无关：库里 `api_keys.key` 目前存的是明文（密钥页能反复显示），快捷指令沿用这一事实，不在本次改哈希方案。

## 14. 分发、版本、系统要求

| 项 | 选择 |
| --- | --- |
| 主分发 | iCloud 快捷指令链接（用运营用的 Apple ID 制作并分享） |
| 备分发 | 站点托管 `static/shortcuts/media-parser.shortcut`，落地页同时给文件下载 |
| 二维码 | 落地页放安装链接的码，方便从电脑扫到手机 |
| 系统 | iOS 16+ / iPadOS 16+ / macOS 13+（同一条指令；Mac 上「存储到相册」进照片 App） |
| 不支持 | Apple Watch（下大文件不现实）、Android（不是「快捷指令」；Android 用户继续用网页） |
| 微信/抖音内置浏览器 | 安装链接常被拦，落地页 FAQ 写「用 Safari 打开」 |

版本号写在主指令第一条注释和设置页顶部。v1 **不做**在线强制更新检查（又一个接口，收益小）。要更新时改落地页文案 + 换 iCloud 链接。用户的 `api-key.txt` 不受影响。

制作时用中文 iOS 导出；权限会在用户第一次运行时由系统询问：网络、相册、文件、剪贴板。我们无法跳过系统权限框，也不该用说明页把这些话再说一遍。

## 15. 明确不做（避免繁琐）

- 付费、积分商城、在快捷指令里「去充值」
- 用户名密码登录、验证码、邮箱
- 按平台拆多条指令
- 真正的系统实况照片封装（v1）
- 批量队列、定时抓取、收藏夹同步
- 快捷指令内预览播放器（下完进相册，用系统相册看）
- 新的 `/api/v1/me`、`/api/v1/shortcut/config` 之类端点
- Android / 鸿蒙「指令」——需要另一套分发，单独立项
- 把体验页 `/api/parse`（免 Key、有频率限制、只给官网演示用）接到快捷指令——会和「密钥必传」冲突，也没有调用日志归属

## 19. 和接口文档的差异（实现时以代码为准）

| 点 | `dist/接口文档.md` | 代码 / 本设计 |
| --- | --- | --- |
| 文本长度 | 2048 | **2000**，快捷指令按 2000 截 |
| 推荐调用 | GET + Query `key` 也可以 | 快捷指令**只**用 POST + Bearer |
| 体验接口 `/api/parse` | 未强调区分 | 快捷指令禁止使用（免 Key、不记到该用户） |
| 付费 | 提到 402 | 接住错误，不做付费 UI |

解析字段、`succ` 判断、`image_list` 两种形态、错误码表——与 `dist/接口文档.md` 一致，快捷指令按该文档消费。
